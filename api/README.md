# API моделей PicPac — подготовленный каркас

Версия 1.1, 12.11.2026. Локальное удаление фона документов уже работает в браузере. Этот каталог относится к отдельной **творческой обработке обычных фотографий и иллюстраций**. В публичном MVP облачная генерация отключена; ключи не добавлены, внешние вызовы с фотографиями не выполняются.

## Схема

```text
Телефон → системная галерея → IndexedDB (неизменные оригиналы)
    ├─ Документы: MediaPipe на устройстве → отдельная копия → контроль
    └─ Творческая студия: 1–3 снимка + запрос + согласие
            → PicPac API с авторизацией → сервер PicPac с моделью
            → закрытый результат → сравнение → новый вариант в проекте
```

Пользователь из Беларуси покупает услугу у PicPac. Закупку вычислений и договор с провайдером осуществляет PicPac. Оплата клиентом ещё не реализована: текущие заказы тестовые.

## Подключение для разработчика

1. Развернуть собственный inference gateway и закреплённую модель. Контракт ниже — **контракт PicPac**, а не готовый нативный endpoint Qwen, Yandex или Alibaba. Нужен обслуживающий модель адаптер.
2. Создать серверный `api/.env` по `.env.example`. Передавать значения через хранилище секретов хостинга; не помещать ключи в `dist`, репозиторий, URL или localStorage.
3. Подключить реальную авторизацию PicPac. Сервер входа выдаёт короткую HS256-сессию; фронтенд вызывает `setAiSession({accessToken: async () => sessionToken})`. Модельный ключ никогда не попадает в эту функцию. Локальный профиль MVP не выдаёт сессию.
4. Запустить локальный сервер Node 20.6+: `node --env-file=api/.env server.mjs`. Без настройки возвращается `connected:false`. Сервер слушает только localhost.
5. Для публичного сервиса разместить backend отдельно и настроить reverse proxy `/api/ai/` на том же origin приложения. Текущий Sites-деплой статический: публикация этого каталога **не запускает Node API**. После подключения поменять `dist/ai-config.json` на `apiBase: "/api/ai/"`.
6. До включения реальных платежей подключить серверный баланс/резервирование стоимости, возвраты, журнал расхода, базу/очередь заданий и объектное хранилище. Текущий файловый журнал предназначен для одного процесса и интеграционных испытаний, не для нескольких реплик.

Переменные: `PICPAC_AI_ENABLED=true`, `PICPAC_AUTH_SECRET` (не менее 32 символов случайного секрета), `PICPAC_MODEL_GATEWAY_URL` (HTTPS), `PICPAC_MODEL_GATEWAY_KEY`, `PICPAC_EDIT_MODEL`. `PICPAC_GENERATE_MODEL` задаётся отдельно и только для модели текстовой генерации; без него иллюстрации недоступны. HTTP допустим лишь для явно включённого локального inference gateway. Укажите `PICPAC_PUBLIC_ORIGIN` фактического интерфейса.

JWT: `alg=HS256`, `iss=picpac`, `aud=picpac-ai`, `sub` — идентификатор пользователя, `exp` не далее 24 часов от проверки, необязательный `nbf`. Для производства предпочтительна короткая сессия с обновлением через сервер входа. Публичного endpoint выдачи токенов в этом каркасе нет.

## API приложения

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/api/ai/capabilities` | Доступные операции; без авторизации, без секретов. |
| POST | `/api/ai/jobs` | Создать задание. Bearer-сессия и `Idempotency-Key` 16–128 символов обязательны. |
| GET | `/api/ai/jobs/:id` | Статус только собственного задания. |
| GET | `/api/ai/jobs/:id/result` | JPEG только владельцу; `Cache-Control: no-store`. |

Тело создания:

```json
{
  "operation": "photo.edit",
  "prompt": "Спокойный сад на фоне, сохранить лицо и естественную текстуру кожи",
  "references": [{"mimeType": "image/jpeg", "data": "BASE64_BYTES"}],
  "consent": true
}
```

`photo.edit` требует 1–3 JPEG/PNG/WebP до 5 МБ каждый. `art.generate` требует пустой список исходников. Документных операций в этом API нет. JSON до 22 МБ, запрос до 2000 символов; сервер проверяет сигнатуру файла, клиент передаёт JPEG с длинной стороной до 1600 px. Для полноценного production ingress добавить декодирование, лимит пикселей и повторное безопасное кодирование на сервере.

Ответ задания: `id`, `status` (`queued/running/succeeded/failed`), даты, `operation`, безопасная ошибка, результат при готовности. Повтор с тем же ключом и телом возвращает то же задание; другое тело с тем же ключом → 409. Новый осознанный запрос требует нового ключа. Автоматического повтора платного вызова нет.

Ограничения каркаса: два активных задания на пользователя, четыре на процесс, двадцать в сутки на пользователя; последние два настраиваются. Лимиты действуют внутри одного процесса. Источники и запрос не записываются на диск. JPEG хранится один час с момента создания задания, уборка выполняется при запуске, запросе истёкшего результата и раз в минуту. Метаданные журнала сохраняются для идемпотентности; их срок хранения перед production нужно определить отдельно. После перезапуска незавершённые задания отмечаются как failed и не запускаются повторно.

## Контракт PicPac inference gateway

Backend отправляет `POST /v1/images/edit` или `/v1/images/generate` на доверенный адрес из окружения, `Authorization: Bearer MODEL_GATEWAY_KEY`:

```json
{
  "model": "Qwen-Image-Edit-2511",
  "prompt": "...",
  "images": [{"mime_type":"image/jpeg", "base64":"..."}],
  "n": 1,
  "output_format": "jpeg",
  "preserve_identity": true
}
```

Gateway возвращает `{"model":"...", "data":[{"b64_json":"JPEG_BASE64"}]}`. `preserve_identity` — указание адаптеру, не гарантия сохранения внешности. Результат до 15 МБ JPEG, ответ до 22 МБ; timeout 120 секунд. URL результатов и HTTP-редиректы отклоняются; произвольные адреса из пользовательского тела не запрашиваются.

Фронтенд сохраняет номер задания, опрашивает статус, показывает вариант и добавляет его только по явному нажатию. Закрытие студии прекращает опрос, но не отменяет уже начатые вычисления. Автоматического восстановления опроса после закрытия пока нет; результат можно получить по сохранённому `aiJobId` через API. До коммерческого запуска реализовать экран незавершённых задач/отмены и показать пользователю стоимость до запуска.

## Критерии качества перед включением

Сравнить модели на согласованном наборе снимков PicPac: дети/взрослые, очки, тёмные волосы, сложный фон, низкий свет, архивные фото. Проверять лицо, руки, надписи, естественность кожи и края. Художественные реконструкции обозначать как творческие варианты; не представлять придуманные сцены как реальные события. Изображения для документов в этот генеративный контур не направлять. Для документов США сохранять оригинал в соответствии с [официальными требованиями](https://travel.state.gov/content/travel/en/us-visas/visa-information-resources/photos.html).

`node --test tests/*.test.mjs` проверяет доменные ограничения, подпись сессии, изоляцию владельцев, идемпотентность и ограничения адаптера. Реальные платные модели тестами не вызываются.
